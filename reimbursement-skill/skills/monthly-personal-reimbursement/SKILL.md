# 月度个人报销

根据当期报销清单，将发票、费用与所属主体逐项对应。按用户本轮要求执行下载、核对、更新 Excel 或打包。用户说“做这个月报销”且未缩小范围时，串起这些步骤。遵守当前工作区适用的数据访问规则。

## 确认本期范围

- 以用户最新确认的清单及实际保存的工作簿为依据。定位工作表、当期分组、来源行、费用金额和已有发票号。台账已更新时重新读取。指令与台账不一致时，按用户指令执行，并说明差异。
- 使用本轮明确的路径和账号。需要补足定位信息时读取 [个人配置指南](references/local-profile.md) 所述的本机配置。用户已提供足够信息时可直接执行对应步骤。
- 核对报销月份和落盘目录。费用发生、通行、开票和收到邮件的日期可以不同。已有目录名与当期不符时，结合用户指令和最新台账确认，避免写到往期。
- 沿用当期台账和用户指定的主体分组。根据票面购买方确认归属，存在跨主体、退款、红票或同一发票涉及多个项目时，查清依据再计入。

## 查找和核对

- 先查当期目录的原件，确认是否已下载或已在往期报销。缺票时使用本轮授权且确能访问目标收件箱的连接或已登录客户端，覆盖可能的跨月补发。附件和可信开票链接都可用，同一通知的重复邮件按完整票号去重。客户端登录身份与实际收件箱可能不同。链接受限、权限不足或用户停止操作时，按工具要求处理并报告缺口。
- 按项目匹配原票，核对购买方、品名、开票日期、价税合计及费用依据。一笔有多张票时逐张对应，包括拆开的运费票。付款通知和订单可辅助定位。表里只有票号尾段时，用唯一原件、品名和金额交叉核对。按完整票号去重，必要时比较原件哈希。
- 核对通行费的日期、出入口、对应票号及累计金额。打开原邮件附件或 ZIP 里的明细 PDF 核实内容。有按行程索引和按票据索引两个版本且列的是同一组数据时，行程单包优先用按行程索引版本。若只有票面列明通行时刻与出入口，保留该原票并说明独立明细的取得情况。
- 缺原票、部分缺票、抬头或金额有差异的项目标注原因。保留已取得票据与费用行的对应。开票、对外发送和提交报销需要另外授权。

## 整理文件和更新台账

- 下载或改名时，名称显示主体、项目和金额。多张同金额票可追加发生日期、运费标签或票号尾段。PDF、XML、OFD 属于同一张票时可统一名称主干。遇同名先比较字节，保留内容不同的现有文件。
- 更新 Excel 时，在本期项目旁把完整票号写成文本，避免 Excel 截断长数字，多张票号可换行。小计和合计引用本期明细。区分已齐与待补票时，按核验状态计算，并列明部分缺票项目的已取得金额。复核原金额、公式和本期引用范围。
- 用户要求美化往期时，可统一相关标题、金额小数位和合计样式，保留历史公式、批注、已有标记和工作簿结构。原位保存前核对用户是否有尚未保存的改动或文件占用。

## 按主体打包和交付

- 按主体分别打 ZIP，保持原始 PDF 字节。发票与对应的官方通行明细各有目录。需要时在包内按月份重命名明细，避免同名。包名和金额与实际入包金额一致。
- 用户只要“已齐”时，按报销项目判断齐套。部分缺票的项目整项列为待补。用户要求按已取得票据拆分时，再按实际入包金额计入。表内旧汇总与实际票据不符时，以原件核对结果说明差异。
- 文件内容核验后，可依照 [ZIP 打包说明](references/packaging.md) 的清单运行辅助脚本。重开最终 ZIP，核对原件字节、文件数量、无重复发票、各组与总额。将核验后的包放到本轮指定目录并回读。
- 交付列明报销期间、各主体金额、发票与行程单数量、文件链接及缺口。若用户只要求核对和打包，保持 Excel 现有数据。
